01 — The idea

Agent context is scarce. Most of it is wasted.

Code is not a list of strings — it is a graph of definitions, references and calls. Agents were reading it like a flat file.

BEFORE — GREP BLIND

Read more, know less

  • Keyword grep → partial matches, no relationships
  • Whole-file reads burn context on irrelevant lines
  • Cross-file call paths guessed, not traced
  • Fixed tool schemas paid for on every session
  • No signal on what actually paid off
AFTER — TRACE A REAL GRAPH

Ask structure, get structure

  • Name/graph/FTS queries over parsed symbols
  • Bounded file reads — 300 lines by default
  • trace_call_path walks actual CALLS edges
  • Presets cap the schema tax: 5 / 13 / 31 tools
  • get_session_usage measures the spend
Design principleThe agent is the intelligence. NexusContext is the memory — and the meter. No LLM lives in the daemon; it builds structure and answers queries, while the calling agent does all the reasoning.

01 — Design philosophy

Eight principles that constrain every decision

These are not aspirations. Each one rules out a whole class of tempting shortcuts.

01

Agent thinks, NC remembers

No LLM in the daemon. Structure and queries only.

02

Structure over similarity

Graph + FTS5 over what tree-sitter parsed — a deliberate bet, not a missing feature.

03

Measure, don’t claim

Real harness tokens when available; labelled bytes/4 estimates otherwise. Publish the losses.

04

Bound what agents drive

Response caps, depth limits, timeouts, file caps, watcher budget — plus pressure signals.

05

Provenance over convenience

CALLS ≠ CALLS_RESOLVED. Ambiguity stays unresolved, never guessed.

06

Humans approve memory

Agent staging is not approval. No path for an agent to approve its own memory.

07

Local-first by default

No account, no cloud, no egress. Owner-only permissions, portable per-repo artifacts.

08

Reuse what exists

SQLite over a graph DB, tags queries over hand-written grammars, Graphviz over custom layout.

Ninth rule: validate against realityDogfood gates, real-server tests, live daemon verification, release evidence — “speed never buys us confidence.”

03 — Topology

Three ways to run the same engine

All modes converge on the same shared code path — including the cold-project catch-up logic.

PER-SESSION

nexusd mcp

Newline-delimited JSON-RPC over stdio. stdout is reserved for protocol; logs go to stderr only.

  • No watcher, no socket
  • Ideal for IDE / agent hosts
  • Works on all tiers including Windows
nexusd mcp # stdin ↔ stdout
LONG-LIVED

nexusd serve

Systemd --user daemon with a Unix-domain-socket control API and a background watcher.

  • status.get · projects.* · config.*
  • search.adhoc · viz.call_graph
  • Linux and macOS only
nexusd serve # $XDG_RUNTIME_DIR socket
HUMAN

nexus CLI

The same shared engine, driven by a person: index, query, export, configure, approve memory.

  • nexus reindex --deep
  • nexus memory skill-approve
  • Same touch_and_catchup path
nexus search "handler" # shared path

04 — Data & memory

The data model: a small property graph in SQLite

One SQLite database per project. Five node kinds, six edge kinds, plus an FTS5 table and narrow vault metadata.

SCHEMA

Stored as rows, not objects

  • nodes — id, kind, name, qualified_name (unique), file, lines
  • edges — src, dst, kind (indexed both ways)
  • vault_links — target, resolution, confidence, line
  • vault_aliases — alias → file
ON DISK

One DB per project

~/.local/share/nexuscontext/<hash>/graph.db — WAL mode, 30 s busy timeout, 0600 file / 0700 dir. Legacy embedding tables are dropped on open.

04 — Memory architecture

Three memories, deliberately different

Each memory has its own source of truth, its own decay semantics, and its own gate. They share one daemon and one ledger.

STRUCTURAL

What the code is

graph.db — SQLite property graph + FTS5 per project.

  • Source: tree-sitter graph
  • Stale when: file hash changes
  • Signal: index_freshness
  • Rebuild: full, transactional
PROCEDURAL

How we work

Learned SKILL.md files plus myelin.db.

  • Source: observations + reps
  • Stale when: unused ~30 days
  • Signal: atrophy
  • Context needs: human: approval
DECLARATIVE

What is true

Curated facts in SQLite + git-friendly OKF v0.3 bundle.

  • Source: decisions, incidents, owners
  • Stale when: anchored code changed
  • Signal: stale_after
  • Context needs: human: review
LEDGER

What it cost

Append-only ledger.db, keyed by harness session.

  • Source: harness + estimates
  • Stale: not applicable
  • Signal: never_mixed
  • Reports: injections, tools, usage

06 — Running it

Safe defaults, hard bounds, honest platform tiers

Configuration is intentionally conservative; every agent-drivable surface is capped and observable.

CONFIG

Opt-in by design

  • allowed_roots — canonical containment
  • tools.preset — minimal / standard / full
  • lsp — off; deep only
  • config_index, vault_index — off
  • sources — empty; explicit fan-out
  • Live reload + /reload
BOUNDS

Every surface is capped

  • 200 results · 10 depth · 16 sources
  • 300-line / 300 KB file reads
  • 5 MB per indexed file
  • 5 s query timeout
  • 2 GiB streamed import cap
  • 800-token injection budget
  • Half of inotify max_user_watches
PLATFORMS

Tiered, stated plainly

  • Linux — full parity: MCP, serve, watcher, GUI
  • macOS — CLI + daemon, no GTK
  • Windows — CLI + MCP only; all tools work
  • 6 platform × arch builds
PrivacyOwner-only 0600 / 0700 writes, hardened systemd unit, no outbound call, no API key.

06 — Evidence

Measure, don't claim — including the losses

Real questions, tokenized. The shape of the question matters more than raw file count.

SMALL REPO · 70 FILES

NexusContext itself — 780 nodes / 1,280 edges

  • Dead code: 1 of ~8 candidates found by baseline → 8 found and triaged in 5 calls vs 13
  • Subsystem understanding: ~24% fewer tokens via search_code
  • Implementation location & call path: matched or beaten by rg
LARGE MONOREPO · 391 FILES

9,689 nodes / 18,276 edges / 17 services

  • 3/3 cross-cutting architecture tasks won on tokens; 2/3 on time
  • Alerting pipeline: 86,658 → 59,134 tokens
  • Auth: 54,361 → 38,022 tokens
  • Import-count questions stayed grep's turf
What this actually provesGenuinely better at architecture/location questions and dead-code detection at scale — not at narrow single-pattern lookups. One index_repository amortized across 11 fresh sub-agents with zero marginal reindex; no true restarts or concurrency were tested.
